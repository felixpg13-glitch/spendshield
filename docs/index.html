Why it exists

A wallet can move money. It doesn't decide whether an agent should.

Budget

Can this agent spend $25 right now? Cumulative, atomic, per identity — not just per call.

Authority

Is this action actually authorized? Deterministic policy code, not the model's opinion.

Execution safety

What if the request is replayed, malformed, duplicated, or exceeds policy? Signed single-use grants.

SpendShield sits between agent intent and payment execution.

The difference

A spending limit isn't a spending policy.

Request 1$40 ✓
Request 2$40 ✓
Request 3$40 ✗— daily budget consumed

But real systems also hit retries, parallel agents, duplicate requests, transaction splitting and malformed or injected input. So SpendShield isn't just "$100/day" — it's policy + authorization + enforcement + audit.

How to use it

Three ways in. Pick yours.

Python

Embed SpendShield into your agent or payment workflow.

pip install spendshield Quickstart →

MCP

Add spending controls to MCP-based agents (Claude, etc.).

uvx --from spendshield spendshield-mcp --policy policy.yaml Claude setup →

Payments / x402

Not a wallet

Why it isn't "another agent wallet".

Agent ↓ Intent ↓ ┌────────────────────┐ │ SpendShield │ │ policy │ │ authorization │ │ budget │ │ validation │ │ audit │ └────────────────────┘ ↓ Wallet / x402 / Stripe ↓ Payment

SpendShield decides whether an agent is authorized to spend. Your wallet / payment rail executes the payment.
